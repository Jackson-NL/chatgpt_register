## 3. 当前问题诊断

### 3.1 前端视觉单调

当前界面以基础白底、表格、普通卡片为主，虽然可用，但缺少专业运维控制台的层次感、状态感和品牌感。需要引入更明确的视觉系统：

- 专业 SaaS 运维后台风格。
- 支持暗色/浅色主题规划，至少保证当前浅色主题的 token 化，为后续暗色主题留出结构。
- Bento 卡片、状态流、指标组、实时日志、风险提示区形成信息层次。
- 图表和表格的数据密度提高，但不牺牲可读性。

### 3.2 信息架构不完整

已有页面较多，但导航与业务域之间还不够清晰。建议把产品定位为：

> AccountOps：账号生产、验证、冷却、巡检、导出的一体化控制台。

推荐一级模块：

1. 仪表盘：全局态势。
2. 注册工作台：单号/批量/Gmail 复用池/实时日志。
3. 账号中心：账号生命周期、凭据、安全、导出。
4. Gmail 会话池：订单、别名、验证码次数、过期状态。
5. 健康巡检：账号可用性、失败原因、策略。
6. 代理池：代理质量、使用次数、风险标记。
7. 导入导出：sub2api、JSON/JSONL/CSV、脱敏策略。
8. 审计日志：敏感操作留痕。
9. 设置中心：SMSBower、注册策略、冷却、导出、安全展示。

### 3.3 操作流缺少引导

注册不是单次提交表单，而是多阶段流程：租邮箱/取别名、提交邮箱、设置密码、接收验证码、填写验证码、补充资料、获取 token、冷却、巡检。前端需要明确展示流程阶段，而不是只显示“running/success/failed”。

### 3.4 状态可观测性不足

需要加强：

- 任务阶段进度条。
- 实时日志。
- 当前 Gmail 订单状态。
- 验证码等待状态、轮询次数、最后一次响应。
- 失败原因归类：验证码失败、风控、代理失败、浏览器异常、token 提取失败、2FA 绑定失败等。
- 后端接口错误展示要包含恢复建议。

### 3.5 账号生命周期管理不足

账号不应只有成功/失败，需要明确生命周期：

- `created`：已生成但未验证。
- `cooling`：冷却期。
- `active`：可用。
- `risky`：存在风险或异常响应。
- `unhealthy`：巡检失败。
- `paused`：手动暂停。
- `expired`：凭据过期或 Gmail session 失效。
- `deleted`：删除前确认。

### 3.6 安全与凭据展示边界不足

涉及敏感信息：邮箱、密码、access_token、refresh_token、id_token、TOTP secret、代理凭据、SMSBower key。前端应默认脱敏，明文展示必须满足：

1. 用户显式点击“显示”。
2. 对高风险字段二次确认。
3. 自动隐藏，例如 30 秒后恢复脱敏。
4. 复制操作写入审计日志。
5. 列表页不展示完整明文，只在抽屉/弹窗中展示。

## 4. 总体改造目标

把项目升级为“账号生产与运维控制台”，目标包括：

1. 视觉：从普通表单页升级为专业、数据密集、状态清晰的 SaaS 运维后台。
2. 信息架构：补齐导航、路由和页面分工，让用户知道每个模块解决什么问题。
3. 注册工作台：把 Gmail/SMSBower、单号注册、批量注册、任务日志、验证码状态放在一个可观测流程里。
4. 账号中心：支持生命周期、健康状态、2FA 覆盖率、凭据抽屉、批量操作、导出。
5. Gmail 会话池：明确展示当前订单、剩余可用次数、已用 alias、SMSBower 状态和过期原因。
6. 巡检与审计：健康检查和敏感操作留痕要成为一级功能。
7. 安全：敏感字段默认脱敏，明文展示可控、可审计、可自动隐藏。
8. 可维护：尽量复用现有 UI 组件和 API 客户端，不新增大型依赖，不重写项目。

## 5. 推荐产品定位

产品名保留或强化为：`AccountOps`。

一句话定位：

> AccountOps 是一个用于账号生产、验证码会话管理、2FA 维护、健康巡检和 sub2api 交付的本地运维控制台。

用户心智：

## 6. UI/UX 设计方向

### 6.1 设计风格

采用“专业 SaaS 运维后台 + 数据密集控制台”风格：

- 主色：蓝色系，表达技术与可靠性。
- 状态色：绿/黄/红/灰，分别表示成功、等待/风险、失败、未知/暂停。
- 页面布局：左侧导航 + 顶部状态栏 + 内容区卡片/Bento/Grid。
- 数据展示：指标卡、趋势图、状态分布、时间线、表格、抽屉详情。
- 图标：统一使用 `lucide-react`，不要用 emoji 作为结构性图标。

### 6.2 色彩系统建议

基于当前 Tailwind 体系，建议建立语义 token，避免组件里散落硬编码颜色：

- `primary`: blue-600 / blue-700
- `success`: emerald-500 / emerald-600
- `warning`: amber-500 / orange-500
- `danger`: red-500 / red-600
- `info`: sky-500 / blue-500
- `neutral`: slate-400 / slate-500
- `surface`: white / slate-50
- `border`: slate-200
- `text-primary`: slate-900
- `text-secondary`: slate-500
- `text-muted`: slate-400

若做暗色主题，先在 CSS 变量层准备，不要求一次性把全项目彻底暗色化。

### 6.3 布局系统

- 页面外层：`space-y-4` 或 `space-y-5`。
- 卡片网格：`grid grid-cols-1 sm:grid-cols-2 xl:grid-cols-4`。
- 主工作台：左侧配置区 + 右侧实时状态/日志区，桌面端双栏，移动端上下堆叠。
- 数据表：保留横向滚动，列密度可配置。
- 详情：统一使用 Drawer，不要在表格行中塞过多敏感字段。

### 6.4 组件规范

优先复用 `frontend/src/components/ui/index.jsx` 中已有组件，必要时增强：

- `StatusBadge`：统一状态色和中文文案。
- `MetricCard` / `StatCard`：统一指标卡。
- `Timeline`：注册阶段、审计、健康事件都可复用。
- `SecretField`：敏感字段脱敏、显示、复制、自动隐藏。
- `StageStepper`：注册阶段进度条。
- `RiskBanner`：重要风险和失败原因展示。
- `PageHeader`：统一页面标题、副标题、主要操作。
- `Toolbar`：统一筛选、搜索、批量操作。

不要引入大型 UI 框架；保留 Tailwind + 当前组件体系。

### 6.5 交互动效

- hover/active/focus 状态统一，动画 150–300ms。
- 加载超过 300ms 时展示 skeleton 或小型 loading。
- 任务阶段切换可以用轻量 transition，不要阻塞交互。
- 支持 `prefers-reduced-motion`，避免强制大幅动效。

### 6.6 可访问性

- 所有 icon-only button 必须有 `title` 或 `aria-label`。
- 表单字段必须有 label 或明确的可访问名称。
- 错误信息贴近字段，包含恢复建议。
- 颜色不能作为唯一状态表达，要配合文字/图标。
- 保留可见 focus ring。

## 7. 功能模块完善方案

### 7.1 仪表盘升级

目标：打开首页即可知道系统是否健康、今天跑了多少、失败在哪里、下一步该处理什么。

建议内容：

1. 顶部核心指标：
   - 今日注册成功数。
   - 今日失败数。
   - 注册成功率。
   - 活跃账号数。
   - 冷却期账号数。
   - 2FA 覆盖率。
   - 异常账号数。
   - SMSBower 余额/订单状态（如果后端已支持）。
2. 中部图表：
   - 近 14 天注册趋势。
   - 失败原因 Top 5。
   - 账号状态分布。
   - 代理健康分布。
3. 下部运营队列：
   - 正在运行的注册任务。
   - 需要处理的异常账号。
   - 最近审计事件。
   - Gmail session 即将耗尽/已过期提醒。
4. 快捷操作：
   - 新建注册任务。
   - 复用当前 Gmail 订单。
   - 运行健康检查。
   - 导出可用账号。

### 7.2 注册工作台升级

目标：把 `Register.jsx` 改为清晰的“注册工作台”。

建议分区：

1. 左侧配置面板：
   - 模式：单账号 / 批量 / Gmail 复用。
   - 代理选择或手动代理。
   - headless 开关。
   - 绑定 2FA 开关。
   - Gmail session 开关。
   - 批量目标数、并发数。
2. Gmail 会话卡片：
   - base email。
   - 当前 alias。
   - mail_id。
   - 已用次数 / 最大次数。
   - 状态：active / waiting_code / max_reached / expired / released。
   - 操作：租新邮箱、生成下一个 alias、释放、刷新状态。
3. 任务阶段 Stepper：
   - 准备浏览器。
   - 租/复用邮箱。
   - 提交邮箱。
   - 设置密码。
   - 等待验证码。
   - 填写验证码。
   - 完成资料。
   - 获取 OAuth token。
   - 保存账号。
   - 冷却/验货。
4. 实时日志：
   - 继续使用 `LiveLogBox`。
   - 日志按 level 着色。
   - 支持自动滚动、暂停滚动、复制日志。
5. 结果区：
   - 成功后显示脱敏账号。
   - 凭据只在显式点击后显示。
   - 2FA secret 只在受控抽屉中显示。

### 7.3 Gmail/SMSBower 会话池

建议新增独立页面或在注册工作台内做强展示。若做独立页面，路径建议：`/gmail-sessions`。

功能：

1. 当前活跃订单：
   - `mail_id`
   - `base_email`
   - `alias_counter`
   - 最大可用次数
   - 剩余次数
   - 最近一次验证码状态
   - 过期原因
2. 历史订单：
   - 成功注册数量。
   - 失败数量。
   - 耗尽状态。
   - 释放/过期时间。
3. 操作：
   - 租新订单。
   - 复用下一轮。
   - 释放订单。
   - 标记 expired。
4. 重要约束：
   - 不要在页面加载时自动租两个 Gmail。
   - 用户点击“租新 Gmail”才租新订单。
   - 复用时必须明确调用后端复用/准备下一验证码逻辑。
   - 超过最大验证码次数要进入 expired 状态。

### 7.4 账号中心升级

目标：让账号从“列表记录”变成“可运维资产”。

建议功能：

1. 筛选：
   - 生命周期状态。
   - 健康状态。
   - 2FA 是否绑定。
   - 来源：注册 / 导入 / 手工。
   - 代理。
   - 创建时间。
2. 表格列：
   - ID。
   - 邮箱/手机号（默认部分脱敏）。
   - 状态。
   - 2FA 状态。
   - token 状态。
   - 密码状态/密码摘要（默认脱敏，支持受控显示）。
   - 最近巡检。
   - 代理。
   - 创建时间。
   - 操作。
3. 账号详情抽屉：
   - 基础信息。
   - 凭据区（默认脱敏），至少包含 password、access_token、refresh_token、id_token。
   - 密码区支持复制、显示/隐藏、自动隐藏和审计记录。
   - TOTP 区（默认脱敏）。
   - 健康检查历史。
   - 注册任务关联。
   - 审计记录。
4. 批量操作：
   - 批量巡检。
   - 批量导出。
   - 批量暂停/恢复。
   - 批量打标签。
5. 安全要求：
   - 列表页严禁默认明文展示完整 token/password/TOTP。
   - 账号管理表格可以增加“密码”列，但只能展示脱敏摘要，例如 ******** 或首尾掩码；用户点击显示后短暂展示明文。
   - 复制 password、token、TOTP 等敏感字段要 toast 提醒，并建议后端记录审计。

### 7.5 2FA 管理

建议做成账号详情中的 Tab，也可以做独立筛选视图。

功能：

1. 待绑定 / 已绑定筛选。
2. 手动写入 TOTP secret。
3. 校验 TOTP secret 格式。
4. 可选显示当前 TOTP code，但必须默认关闭，打开需二次确认且自动隐藏。
5. 展示绑定来源：自动绑定 / 手工写入。
6. 展示绑定时间与操作者。
7. 所有写入、显示、复制动作进入审计日志。

### 7.6 健康检查与巡检

`Health.jsx` 已存在，应接入一级导航。

建议强化：

1. 健康评分。
2. 巡检队列。
3. 失败率。
4. 平均耗时。
5. 失败原因 Top 5。
6. 策略列表：每日/每小时/手动。
7. 单账号立即检查。
8. 检查详情抽屉：请求阶段、错误、建议恢复动作。

### 7.7 代理池与风控

建议强化 `Proxies.jsx`：

1. 代理健康状态：ok / slow / banned / failed / unknown。
2. 延迟、失败次数、最近使用时间、成功注册数量。
3. 国家/地区标签。
4. 与任务/账号关联。
5. 风险提示：同一代理连续失败、疑似风控、验证码阶段失败聚集。
6. 一键测试代理。

### 7.8 审计日志

`Audit.jsx` 已存在，应接入一级导航。

必须记录/展示：

1. 显示敏感字段。
2. 复制敏感字段。
3. 明文导出。
4. 删除账号。
5. 写入 2FA。
6. 修改设置。
7. 租用/释放 Gmail session。
8. 批量注册启动/取消。

### 7.9 导入导出 / sub2api

`Transfer.jsx` 已存在，应接入导航或整合进账号中心。

功能：

1. 导出格式：JSON / JSONL / CSV / sub2api import-codex-session。
2. 字段选择。
3. 脱敏开关。
4. 明文导出二次确认。
5. 导出后生成记录。
