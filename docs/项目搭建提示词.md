# 任务提示词:Codex 注册机(账号批量注册管理系统)

## 项目背景

构建一个 Codex/ChatGPT 账号注册管理系统(注册机),实现:
1. 批量注册 ChatGPT/Codex 账号(手机号注册方式)
2. 管理注册成功的账号(凭据、状态、体检)
3. 注册完成后产出可导入 sub2api 的 OAuth 会话凭据
4. 风控检查(注册过程拦截判定、注册后账号体检、周期巡检)
5. 前端管理界面(任务、账号、代理池、设置)

**当前阶段只做手机号注册,邮箱注册后续再说。**

## 注册流程(基于 mitmproxy 抓包确认的事实,必须严格遵循)

真实浏览器(Camoufox)内执行:

1. `GET https://auth.openai.com/api/accounts/authorize`
   - OAuth 入口,302 跳转 login_url
   - client_id 固定:`app_X8zY6vW2pQ9tR3dE7nK1jL5gH`
2. `POST https://auth.openai.com/api/accounts/authorize/continue`
   - 请求体:`{"username":{"value":"+57...","kind":"phone_number"},"screen_hint":"login_or_signup"}`
   - 前置:获取 sentinel token(flow=authorize_continue)
   - 成功 200,失败可能 403(需要重取 sentinel)
3. `POST https://auth.openai.com/api/accounts/user/register`
   - 请求体:`{"password":"明文","username":"+57..."}`
   - 前置:获取 sentinel token(flow=username_password_create)
   - 成功返回 continue_url
4. `GET https://auth.openai.com/api/accounts/phone-otp/send`(302)
5. `POST https://auth.openai.com/api/accounts/phone-otp/verify`(端点推断,请求体推测 `{"phone_number":"+57...","code":"123456"}`,实现时用 Camoufox 页面内操作完成,不必硬编码)
   - 前置:获取 sentinel token(flow=verify_phone_otp)
6. 跟随 OAuth 回调,获得 access_token / refresh_token / id_token + account_id / plan 信息
7. OTP 未收到/超时:`POST /api/accounts/phone-otp/resend`(可能 400 fraud_guard)

### Sentinel token 机制(关键,不要尝试纯 HTTP 模拟)

- 每个业务请求前:`POST https://sentinel.openai.com/backend-api/sentinel/req`,请求体 `{"p": <行为指纹对象>, "id": <device_id>, "flow": <flow名>}`
- flow 取值:`username_password_create` / `authorize_continue` / `verify_phone_otp` / `password_verify`
- 响应中得到 `openai-sentinel-token`(部分请求还需 `openai-sentinel-so-token`)
- 有效期 540s
- `p` 内含行为指纹(UA、时间戳、事件计数、性能采样),**纯 HTTP 模拟不可行,必须走真实浏览器**
- 实现方式:在浏览器页面上下文内执行 sentinel 请求(与页面同源),用 Playwright `page.route` 或页面内 fetch 截获 token,注入后续请求

### 已知失败场景(抓包实录)

| 现象 | 原因 | 处理 |
|---|---|---|
| 401 invalid_username_or_password | 密码错误 | 重试/换密码 |
| 403 authorize/continue | sentinel token 过期 | 重取 sentinel 后重试 |
| 400 fraud_guard | 风控拦截(IP/设备/号段) | 标记失败,换代理/换号段/换 profile |
| OTP 未收到 | 接码平台延迟/号码回收 | resend(注意 fraud_guard)或取消激活换号 |

## SMSBower 接码平台集成

端点:`https://smsbower.app/stubs/handler_api.php`,全部 GET,参数带 `api_key`。
**重要:请求必须带浏览器 User-Agent(如 `Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/126.0.0.0`),否则被 403 拦截。**

- `getBalance` → `ACCESS_BALANCE:12.34`
- `getNumber&service=dr&country=33&maxPrice=0.05` → `ACCESS_NUMBER:<activationId>:<phone>`
  - service=dr 表示 OpenAI;country=33 哥伦比亚(已验证可用,单价 ~$0.033)
  - 价格上限按用户要求 ≤0.05
- `getStatus&id=<activationId>` → `STATUS_WAIT_CODE` | `STATUS_OK:123456`
- `setStatus&status=1|3|6|8&id=<activationId>`:
  - 1 号码就绪;3 重发;6 完成激活;8 取消(2 分钟内可退)
- `getPricesV3&service=dr` → 各国家/provider 价格(选号用)

取号状态机:取号 → setStatus(1) → 触发浏览器发送 OTP → 轮询 getStatus(3-5s 间隔,上限 120s)→ 收到码填入 → setStatus(6);号码不合适 setStatus(8)。

参考实现:`D:\PRO\archive\phone-sms\providers\smsbower.js`(已跑通的协议实现,可参考移植思路)。

## sub2api 对接(产出格式)

目标接口:`POST <sub2api>/api/v1/admin/accounts/import/codex-session`

账号数据要求(Codex auth.json 风格 JSON,单对象/数组/JSONL 均可):

```json
{
  "tokens": {
    "access_token": "eyJ...",
    "refresh_token": "rt_xxx",
    "id_token": "eyJ..."
  },
  "email": "+57... 或 email",
  "chatgpt_account_id": "user-xxx",
  "chatgpt_user_id": "user-xxx",
  "chatgpt_plan_type": "free"
}
```

- `refresh_token` 必填(缺失无法自动续期)
- 注册机产出:注册完成从 OAuth 会话提取全字段(access/refresh/id_token、email=手机号、account_id/user_id/plan_type 从 JWT claims)
- 落地方式:一键导出 JSON 文件 + 可选自动推送(sub2api 地址可配置)

## 数据模型(SQLite)

- `Account`:id, phone, password, access_token, refresh_token, id_token, account_id, user_id, plan_type, proxy, profile_path, status(active/suspended/expired), created_at, last_check_at
- `Task`:id, status(pending/running/otp_waiting/success/failed/cancelled), phone, country, proxy, concurrency_group, error, created_at
- `SmsActivation`:id, task_id, activation_id, phone, service, status, cost, raw
- `Proxy`:id, url, country, status(ok/banned), used_count, last_used_at
- `HealthCheck`:id, account_id, check_type(register/full/periodic), result, detail, checked_at

## 风控三层

1. 注册过程中拦截:fraud_guard/403/401 实时判定,失败即中止任务、标记代理与号段、换号重试
2. 注册后账号体检:注册完成用该账号发一次轻量请求(拉取 settings/usage),验证凭据可用
3. 周期巡检:定时用 refresh_token 刷新 access_token 验证存活,失效标记并触发重新登录(SSO 重登走 Camoufox + 该账号 profile/代理)

## 前端页面

- 仪表盘:账号数/成功率/今日注册/风控拦截统计(3s 轮询)

- 账号列表:状态、体检结果、导出 sub2api JSON(一键)
- 代理池管理:增删改、状态标记
