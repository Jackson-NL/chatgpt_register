# 步骤 3 完整历程：OpenAI 注册机 — 冒烟测试跑通全链路

## 项目概述

`D:\PRO\openai-register` — 一个 ChatGPT/Codex 手机号批量注册机。后端 FastAPI + SQLite，前端 Vite+React，浏览器驱动使用 Camoufox（基于 Firefox 的指纹伪装浏览器）。

**当前目标**：步骤 3 — 用真实浏览器 (Camoufox) 单账号手动跑通"取号 → 注册 → OTP → OAuth 换 token"全链路。

| 函数 | 作用 |
|---|---|
| `normalize_phone_number(phone, dialing_code)` | E.164 号码规范化，返回 `(e164, national_number)` |

| `submit_phone_form(page)` | 提交手机号表单，含 `__submitPendingForm` 回退 |
| `page_errors(page)` | 提取页面上的错误提示文本 |
| `wait_for_page_transition(page, prev_url, patterns, timeout)` | 等待页面 URL 跳转到匹配模式 |

注册流程（`register()` 方法，342-516 行）：
1. SMSBower 取号 → setStatus(1)
2. 标准化号码 → 打开 Camoufox 浏览器
3. 加载 OAuth authorize URL → 自动跳转到 `/log-in`
4. 点击 "Continue with phone" → 切换到手机号模式
5. 通过 `select_country` 设置国家代码为 CO
6. 通过 `set_react_input_value` 填入本地号码
7. 校验 hidden input `name="phone"` 值是否为 `+57xxxxxxxx`
8. 提交表单 → 等待页面跳转到密码/OTP 页
9. 密码页：填入密码 → 提交 → 等待 OTP 页
10. OTP 页：轮询 SMSBower 获取验证码 → 填入 → Verify
11. 捕获 OAuth 回调 code → 交换 token
12. 异常时 finally 自动 setStatus(8) 释放号码

## 当前卡点

### 现象
冒烟测试运行到表单提交步骤时失败：
```
FAIL: RegisterError phone: 页面没有进入下一步
```

### 截图错误
页面 `https://auth.openai.com/log-in?usernameKind=phone_number` 显示：
```
Oops, an error occurred!
JSON.parse: unexpected character at line 1 column 1 of the JSON data
```

### 原因分析
OpenAI 登录页的 React 应用在提交手机号后，尝试解析服务端返回的 JSON 数据，但服务端返回了非 JSON 内容（Cloudflare 质询页面 HTML 或错误页面），导致 `JSON.parse` 失败。页面停留在 `/log-in?usernameKind=phone_number` 不跳转。

### 已尝试的代理节点（均报相同错误）
| 节点 | 类型 |
|---|---|
| 🇺🇸美国高速01|CTCU|0.1x | 通用 |
| 🇺🇸美国高速02|CTCU|0.1x | 通用 |
| 🇸🇬新加坡高速01|BGP|CTCUCM | 通用 |
| 🇺🇸美国洛杉矶01|流媒体|0.01x | 流媒体 |

### 可能的原因
1. **代理 IP 被 OpenAI/Cloudflare 标记** — 所有代理节点 IP 均为机房 IP，被识别为代理/爬虫流量
2. **Cloudflare Turnstile 挑战** — 页面加载 Sentry SDK 时可能触发了 Turnstile，导致后续请求被拦截
3. **OpenAI 风控升级** — 可能对已知的代理 IP 段返回 JSON 解析错误而非正常登录页
