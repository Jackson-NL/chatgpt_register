## 2. 注册完整时序(手机号 + 密码流程)

用户本次实际走的流程:`login_or_signup` → 输入手机号 → 创建密码 → 手机 OTP 验证 → (被 fraud_guard 拦截)。

```
① GET  /api/accounts/authorize                → 302 (OAuth 入口,种会话 cookie)
   ↓ 302 到 /log-in-or-create-account
② POST /api/accounts/authorize/continue       → 200 (提交手机号,判断账号状态)
   ↓ 响应 JSON: page.type=create_account_password (新号 → 走注册)
③ POST /api/accounts/user/register            → 200 (创建账号:用户名+密码)
   ↓ 响应 JSON: continue_url=/api/accounts/phone-otp/send, method=GET
④ GET  /api/accounts/phone-otp/send           → 302 (触发 OTP 下发)
   ↓ 302 到 /contact-verification (OTP 输入页)
⑤ POST /api/accounts/phone-otp/verify         ← 本次未成功执行(被风控)
⑥ POST /api/accounts/phone-otp/resend         → 400 (fraud_guard 拦截,OTP 重发被拒)
```

> 登录场景(已存在账号)分支:② 的响应变为 `page.type=create_account_password` 之外的类型(如 `password`),走 `POST /api/accounts/password/verify`。

## 3. 核心接口规格

### 3.1 OAuth 入口

```
GET https://auth.openai.com/api/accounts/authorize
```

| 参数 | 值(本次) | 说明 |
|---|---|---|
| client_id | `app_X8zY6vW2pQ9tR3dE7nK1jL5gH` | ChatGPT Web 固定值 |
| scope | `openid email profile offline_access model.request model.read organization.read organization.write` | 固定 |
| response_type | `code` | 固定 |
| redirect_uri | `https://chatgpt.com/api/auth/callback/openai` | 固定 |
| audience | `https://api.openai.com/v1` | 固定 |
| device_id | UUID | 每次会话随机,**需与后续 cookie 一致** |
| ext-oai-did | 同上 | 与 device_id 相同 |
| auth_session_logging_id | UUID | 每次会话随机 |
| screen_hint | `login_or_signup` | 登录/注册切换 |
| login_hint | `+573112317719` | 预填账号(可选) |
| ccaps | `login_methods` | 固定 |
| state | 随机字符串 | OAuth state |

响应 `302`,Location 到 `/log-in/password` 或 `/log-in-or-create-account`,**Set-Cookie 种 8 个会话 cookie**(见 §5)。

### 3.2 提交用户名(判定注册/登录分支)

```
POST https://auth.openai.com/api/accounts/authorize/continue
Content-Type: application/json
```

请求体(92 字节):

```json
{"username":{"value":"+573337348636","kind":"phone_number"},"screen_hint":"login_or_signup"}
```

- `kind`:`phone_number` 或 `email`
- `screen_hint`:`login_or_signup` / `signup` / `login`

响应 200(922~1110 字节):

```json
{
  "continue_url": "https://auth.openai.com/create-account/password",
  "method": "GET",
  "page": {"type": "create_account_password", "backstack_behavior": "default"},
  "oai-client-auth-session": {
    "app_name_enum": "chat",
    "country_code_hint": "GB",
    "openai_client_id": "app_X8zY6vW2pQ9tR3dE7nK1jL5gH",
    "original_screen_hint": "login_or_signup",
    "passwordless_disabled": false,
    "requested_oauth_scopes": ["email","model.read","model.request","offline_access","openid","organization.read","organization.write","profile"],
    "session_id": "authsess_9WlUUd7owy57Qalc0mU2fCr1",
    "signup_source": "",
    "username": {"kind": "phone_number", "value": "+573337348636"},
    "phone_number": "+573337348636"
  }
}
```

- `page.type` 决定下一步:新号=`create_account_password`(注册),老号=`password`(登录)
- `continue_url` + `method` = 下一步应请求的地址

> 注:本次抓包中该接口出现过 403(flow 472、611),发生在 sentinel token 过期后重试时,属风控惩罚,非正常响应。

### 3.3 创建账号(注册核心接口)

```

Content-Type: application/json
```

## 4. sentinel 风控 token 机制(核心难点)

所有业务 API(§3.2~3.6)都要求两个自定义 header:

| Header | 结构 | 是否必须 |
|---|---|---|
| `openai-sentinel-token` | JSON:`{p, t, c, id, flow}` | 必须 |
| `openai-sentinel-so-token` | JSON:`{so, c, id, flow}` | 部分端点(如 authorize/continue) |

### 4.1 签发方式

```
POST https://sentinel.openai.com/backend-api/sentinel/req
Content-Type: application/json
```

请求体(以 §3.3 register 前的请求为例,694 字节):

```json
{
  "p": "gAAAAACWzI3NzQsIkZyaSBBdWcgMTQgMjAyNiAxOTo0NDozMyBHTVQrMDgwMCAo5Lit5Zu95qCH5YeG5pe26Ze0KSIsNDM5NTYzMDU5MiwxNiwiTW96aWxsYS81LjAgKFdpbmRvd3MgTlQgMTAuMDsgV2luNjQ7IHg2NCkgQXBwbGVXZWJLaXQvNTM3LjM2IChLSFRNTCwgbGlrZSBHZWNrbykgQ2hyb21lLzE1MS4wLjAuMCBTYWZhcmkvNTM3LjM2IiwiaHR0cHM6Ly9zZW50aW5lbC5vcGVuYWkuY29tL2JhY2tlbmQtYXBpL3NlbnRpbmVsL3Nkay5qcyIsbnVsbCwiemgtQ04iLCJ6aC1DTix6aCIsNSwicnVuQWRBdWN0aW9u4oiSZnVuY3Rpb24gcnVuQWRBdWN0aW9uKCkgeyBbbmF0aXZlIGNvZGVdIH0iLCJfcmVhY3RMaXN0ZW5pbmdla25hOHNpMzdzIiwiX19vYWlfc29fc3gwIiw4NjUzMS43OTk5OTk5OTcwMiwiNTgxNmVlNmUtMGE2Yi00NGEyLTkxMWMtODA3MTk4MmY0Njg2IiwiIiwxNiwxNzg2NzA3OTExODQ0LjksMCwwLDAsMCwwLDAsMF0=~S",
  "id": "13079a33-972d-49be-aee8-a4633ac8c5bf",
  "flow": "password_verify"
}
```

- `p`:由前端 SDK 生成,**base64 解码后是数组**(见下),整体由哨兵 SDK 用 WebCrypto + AES-GCM 加密(前缀 `gAAAAA` 即加密密文)
- `flow` 取值(已观测到):`password_verify`、`authorize_continue`、`username_password_create`、`verify_phone_otp`
- 每次业务请求前都会重新向 sentinel 取一次新 token

**`p` 解码内容**(base64 解码后):`[签名时间戳, 4395630592, 指纹计数, UA, sdk.js URL, null, "zh-CN","zh-CN,zh", 事件数, 页面函数名(如 runAdAuction/clipboard/getGamepads 的 native 标识), React 监听器名, "oai_so_sx0" 类标记, 性能毫秒数, 页面 UUID, "", 16, 毫秒级时间, 0×7 设备/行为特征数组]`

> 含义:**token 内嵌了浏览器行为指纹**(按键、剪贴板、游戏手柄、性能采样等),直接伪造 HTTP 请求会被服务端校验拒绝。

### 4.2 签发响应

```json
{
  "persona": "chatgpt-noauth",
  "token": "gAAAAABqfv-iLVLagYKun7CjRQfu...（约 22KB）",
  "expire_after": 540,
  "expire_at": 1786708414,
  "turnstile": {"required": true, "dx": "PBp5bWF3bWBOZR...（加密串）"}
}
```

- `token` 即 `openai-sentinel-token` 的 value(前端组装成 `{p,t,c,id,flow}` JSON)
- `expire_after`:540 秒有效
- `turnstile.required=true` 时,前端还需过 Cloudflare Turnstile(受 `dx` 加密参数控制)

### 4.3 前端 SDK

- 入口:`https://sentinel.openai.com/backend-api/sentinel/sdk.js`(或版本化路径 `/sentinel/20260810913b/sdk.js`)
- 辅助:`frame.html?sv=20260810913b`(隔离 iframe,完成采集后 postMessage 回主页面)
- 版本化路径中的 `20260810913b` 为服务端下发的当前版本号

## 5. Cookie / 会话管理

### 5.1 会话 cookie 清单(auth.openai.com)

| Cookie | 值类型 | 有效期 | 说明 |
|---|---|---|---|
| `oai-login-csrf_dev_3772291445` | 签名串 | 1h | CSRF token,**名称随页面动态变化**(后缀随机) |
| `oai-did` | device UUID | 1y | 设备 ID,= device_id |
| `login_session` | JWT(an8/HS? 签名) | 2700s | **核心会话**,内含 `login_challenge` |
| `auth_provider` | base64 长串 | 2700s | 认证状态机 |
| `hydra_redirect` | 签名 JWT | 2700s | OAuth 流程回放 |
| `oai-client-auth-session` | 签名 JWT(含 username/kind) | 2700s | **当前账号上下文**(注册过程中逐步更新) |
| `oai-client-auth-info` | 签名 JWT | 30d | 最近登录策略 |
| `auth-session-minimized` | ES256 JWT | 2700s | 会话最小化 |
| `auth-session-minimized-client-checksum` | JSON | 2700s | 校验和(内含 `affinity` 加密段) |
| `iss_context` / `rg_context` | 简单值 | 2700s | 上下文标记 |

### 5.2 Cloudflare 层(auth.openai.com + chatgpt.com)

| Cookie | 说明 |
|---|---|
| `cf_clearance` | **JS challenge 通过凭证**(本次出现于 OTP 阶段,说明有二次 challenge) |
| `__cf_bm` | 行为管理 token(每个请求滚动刷新) |
| `__cflb` | 负载均衡路由 |
| `_cfuvid` | 指纹 |
| `oai-sc` | OpenAI 自有的 sentinel challenge 状态(从 sentinel 响应 Set-Cookie 而来,`.openai.com` 域) |

### 5.3 状态流转

- `oai-client-auth-session` 在注册各步骤**逐步更新**:提交手机号后含 `username` → register 后含 `phone_number` 和 `phone_verification_channel: "sms"` → OTP 发送后更新签名
- `login_session.login_challenge` 一旦建立,全程必须保持;换浏览器/清 cookie 需重新走 authorize

## 6. 请求头模板(非遥测)

以 register 请求为例的必带头:

```
content-type: application/json
origin: https://auth.openai.com
referer: https://auth.openai.com/create-account/password
user-agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 ... Chrome/151.0.0.0 Safari/537.36
openai-sentinel-token: {"p":"...","t":"...","c":"...","id":"<device_id>","flow":"username_password_create"}
x-access-flow-invocation-id: <每步随机 UUID>
x-openai-document-navigation-id: <会话内固定 UUID>
accept: application/json
sec-ch-ua / sec-ch-ua-mobile / sec-ch-ua-platform
```

> UA 必须与 sentinel token `p` 中嵌入的 UA 一致;`x-access-flow-invocation-id` 每步重新生成;`x-openai-document-navigation-id` 会话内固定。

## 7. 失败场景与风控特征

| 场景 | 表现 | 原因 |
|---|---|---|
| 密码错误 | 401 `invalid_username_or_password` | 密码不匹配(登录流程) |
| sentinel 过期重试 | 403(authorize/continue) | token 过期(540s)或行为异常 |
| 手机号风控 | 400 `fraud_guard` | 号段被标记(本次 resend 触发) |
| 疑似机器人 | turnstile required + challenge | 需过 Cloudflare Turnstile |
| JS challenge | cf_clearance 出现 | IP/指纹异常时二次验证 |

**风控判定维度**(据 token 内容与现象归纳):
1. 手机号/号段信誉(fraud_guard)
2. 设备指纹 + 行为事件(sentinel `p` 内嵌)
3. IP 信誉(Cloudflare 层)
4. 频率与节奏(会话内多个 403 后触发)

## 8. 对注册机实现的技术结论

1. **纯 HTTP 模拟不可行**:sentinel token 内嵌行为指纹(按键/剪贴板/性能/鼠标),服务端校验 payload 中时间戳与事件一致性;且 `p` 的 AES-GCM 加密密钥在 sdk.js 前端代码内,需逆向 JS 才能离线生成。
2. **推荐路线:真实浏览器驱动**:
   - Playwright/CDP 驱动 Chromium,直接复用 sentinel SDK + Cloudflare 全套 cookie
   - 指纹一致性问题由真实浏览器天然解决
   - 需处理 Turnstile(轮询 challenge / 半自动)
3. **OTP 接收**:注册机需对接接码平台(短信转发),`phone-otp/verify` 提交验证码(端点参数待复抓确认)。
4. **fraud_guard 是最大瓶颈**:即使流程跑通,新号段/批量 IP 仍会被拒;需多 IP + 号段轮换 + 节奏控制。
5. **会话管理**:每个注册会话必须完整持有 §5.1 的 cookie 链(尤其 `login_session` 与 `oai-client-auth-session`),跨步骤重放时逐一更新。

## 10. 表单 DOM 观察与驱动修复(2026-08-15)

- 手机号组件的国家选择是 React ARIA `Select`，可见选项使用虚拟滚动；但辅助 `select[tabindex="-1"]` 包含完整国家列表和 `option[value="CO"]`。
- `input#tel[type="tel"]` 保存本地号码，`input[name="phone"][type="hidden"]` 保存提交用 E.164 号码。验证时应以隐藏字段为准，而不是国家按钮的文案。
- 表单提交按钮的稳定选择器为 `button[type="submit"][name="intent"][value="phone_number"]`。页面存在 `window.__submitPendingForm()` 时，点击后需调用该钩子以完成被暂存的浏览器原生提交。
- 驱动实现通过原生 `value` setter 与 `input`/`change` 事件更新受控组件，先验证 E.164 值再提交；虚拟列表滚动不再是国家选择的前置条件。
