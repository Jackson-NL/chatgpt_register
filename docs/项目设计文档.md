## 3. 注册流程(依据抓包,全部在 Camoufox 内完成)

```
1. GET  /api/accounts/authorize                        # OAuth 入口,302 → login_url
   # client_id 固定: app_X8zY6vW2pQ9tR3dE7nK1jL5gH
2. POST /api/accounts/authorize/continue               # 提交手机号
   # body: {"username":{"value":"+57...","kind":"phone_number"},"screen_hint":"login_or_signup"}
   # 前置: 取 sentinel token (flow=authorize_continue)
3. POST /api/accounts/user/register                    # 注册
   # body: {"password":"明文","username":"+57..."}
   # 前置: 取 sentinel token (flow=username_password_create)
4. GET  /api/accounts/phone-otp/send                   # 发送 OTP → 302
5. POST /api/accounts/phone-otp/verify                 # 提交验证码(推断,未抓到)
   # body: {"phone_number":"+57...","code":"123456"} (推测,待复抓确认)
   # 前置: 取 sentinel token (flow=verify_phone_otp)
6. OAuth 回调: 浏览器跟随 continue_url 完成授权
   # 获得 access_token / refresh_token / id_token + account_id / plan 信息
7. 若 OTP 未收到/超时: POST /api/accounts/phone-otp/resend → 400 fraud_guard
```

### 3.1 sentinel token 机制(关键)

- 每个业务请求前: `POST sentinel.openai.com/backend-api/sentinel/req`,body `{p, id(device_id), flow}`
- flow 取值:`username_password_create` / `authorize_continue` / `verify_phone_otp` / `password_verify`
- 响应: `openai-sentinel-token`(部分请求还需 `openai-sentinel-so-token`)
- 有效期 540s;`p` 内含行为指纹(UA、时间戳、事件计数、性能采样)→ **纯 HTTP 模拟不可行,必须走真实浏览器**
- 实现方式:注册流程中在浏览器页面内执行 sentinel 请求(与页面同源同环境),复用 cookie;用 Playwright `page.route` 或页面内 fetch 截获 token 后注入后续请求

### 3.2 关键失败场景(抓包实录)

| 现象 | 原因 | 处理 |
|---|---|---|
| 401 invalid_username_or_password | 密码错误 | 重试/换密码 |
| 403 authorize/continue | sentinel token 过期 | 重取 sentinel 后重试 |
| 400 fraud_guard | 风控拦截(IP/设备/号段) | 标记失败,换代理/换号段/换 profile |
| OTP 未收到 | 接码平台延迟/号码被回收 | resend(注意 fraud_guard)或取消激活换号 |

## 4. SMSBower 接码模块

参考实现: `D:\PRO\archive\phone-sms\providers\smsbower.js`(协议已跑通,可移植/复用思路)。

### 4.1 端点与协议(sms-activate 兼容)

- Base: `https://smsbower.app/stubs/handler_api.php`(备用域名 `smsbower.page`;web 端点 `/web/stubs/handler_api.php`)
- 全部 GET 请求,参数带 `api_key`
- `getBalance` → `ACCESS_BALANCE:12.34`
- `getNumber&service=$svc&country=$id&maxPrice=$p` → `ACCESS_NUMBER:$activationId:$phone`
- `getStatus&id=$id` → `STATUS_WAIT_CODE` | `STATUS_OK:123456`
- `setStatus&status=$s&id=$id`:
  - `1` 号码就绪(短信已发送)
  - `3` 重发验证码(可带 `lastCode`)
  - `6` 完成激活
  - `8` 取消激活(购买后 2 分钟内可退,`EARLY_CANCEL_DENIED` 表示已超时)
- `getPricesV3&service=&country=` → 各 provider 价格/数量(选号用)

### 4.2 默认配置(archive 项目验证过)

- service code: `dr`(OpenAI),fallback `ot`
- country: `33`(Colombia,兼容 OpenAI 手机号注册的国家)
- maxPrice: `0.015`
- 超时 20s

### 4.3 状态机

```
取号(getNumber) → setStatus(1) → 触发浏览器发送 OTP
  → 轮询 getStatus(间隔 ~3-5s,上限 ~120s)
     ├─ STATUS_OK:code → 填入 OTP → setStatus(6) 完成
     ├─ 超时 → setStatus(3) 重发 → 继续轮询(1 次)
     └─ 号码不合适 → setStatus(8) 取消,换号
```

## 5. sub2api 对接(产出格式)

### 5.1 目标接口

`POST /api/v1/admin/accounts/import/codex-session`
(CLI: `node scripts/sub2api-admin.js accounts import-codex-session --file payload.json`)

### 5.2 账号数据要求

接受 Codex auth.json 风格 JSON(单对象/数组/JSONL 均可),字段:

```json
{
  "tokens": {
    "access_token": "eyJ...",
    "refresh_token": "rt_xxx 或 1//0xxx",
    "id_token": "eyJ..."
  },
  "email": "+57... 或 email",
  "chatgpt_account_id": "user-xxx",
  "chatgpt_user_id": "user-xxx",
  "chatgpt_plan_type": "free"
}
```

- `refresh_token` **必填**(缺失无法自动续期,sub2api 会警告并设过期自动暂停)
- access_token 过期时间从 JWT `exp` 解析(120s 时钟偏移容忍)
- 也支持纯 JSON 字符串或逐行 access_token(但注册机产出一律带全字段)

### 5.3 注册机产出字段

注册完成从 OAuth 会话中提取:

| 字段 | 来源 |
|---|---|
| access_token | OAuth token 响应 |
| refresh_token | OAuth token 响应 |
| id_token | OAuth token 响应 |
| email | 注册手机号(完整 E.164) |
| chatgpt_account_id / user_id | access_token JWT claims |
| plan_type | JWT claims(注册为 free) |
| proxy 信息 | 注册所用代理(可选,sub2api 支持 proxy_id) |

### 5.4 两种落地方式

1. **手动导出**:生成 `accounts.json` 文件,用户在 sub2api 后台/CLI 导入
2. **自动推送**:配置 sub2api 地址 + 管理员凭据(或本地部署时直连),注册完成即调用导入接口

> 注:sub2api 本身有完整账号管理(批量、代理、调度、风控),注册机只负责"制造账号",后续使用/巡检可依赖 sub2api;但"注册后账号体检 + 周期巡检"按用户要求也在本系统实现(§7)。

## 6. 数据模型(SQLite)

```python
class Account:        # 注册成功的账号
    id, phone, password, access_token, refresh_token, id_token
    account_id, user_id, plan_type, proxy, profile_path
    status(active/suspended/expired), created_at, last_check_at

class Task:           # 注册任务
    id, status(pending/running/otp_waiting/success/failed/cancelled)
    phone, country, proxy, concurrency_group, error, created_at

class SmsActivation:  # 接码记录
    id, task_id, activation_id, phone, service, status, cost, raw

class Proxy:          # 代理池
    id, url, country, status(ok/banned), used_count, last_used_at

class HealthCheck:    # 体检/巡检记录
    id, account_id, check_type(register/full/periodic), result, detail, checked_at
```

## 7. 风控三层

1. **注册过程中拦截**:fraud_guard / 403 / 401 实时判定,失败即中止任务、标记代理与号段、换号重试
2. **注册后账号体检**:注册完成后用该账号真实发一次轻量请求(如拉取 settings/usage),验证凭据可用
3. **周期巡检**:定时(如每小时/每日)用 refresh_token 刷新 access_token 验证存活,失效账号标记并触发重新登录(SSO 重登走 Camoufox + 该账号 profile/代理)

## 8. 前端页面(规划)
